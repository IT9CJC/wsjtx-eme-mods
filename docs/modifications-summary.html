Complete Modifications Summary — II9P — September 2026

1. Motivation & Goals

WSJT-X is designed for digital weak-signal communication. EME CW operators on microwave bands (10 GHz and above) need capabilities that the stock program does not provide:

  • CW mode control via CAT — commanding the transceiver into CW mode while retaining full Doppler tracking
  • Large TX frequency shifts — separate RX and TX frequencies offset by up to 200 MHz for transverter setups
  • Fixed frequency offsets — static IF corrections for transverter chains with different RX/TX LO frequencies
  • Operation without a connected rig — computing and displaying Doppler corrections for planning, even when the station hardware is not connected

All modifications preserve the original WSJT-X functionality. Digital modes (FT8, JT65, Q65, etc.) continue to work exactly as in the upstream release.

3. CW Rig Mode via CAT

A new CW radio button has been added to Settings > Radio > Mode, alongside the existing USB, Data/Pkt, and other options.

How it works

  • When selected, the program commands the transceiver into CW mode through Hamlib using RIG_MODE_CW.
  • Doppler tracking remains fully active on both RX and TX — the frequency is continuously updated via CAT just as it is in USB/Data modes.
  • The audio processing pipeline is unchanged. WSJT-X still generates and decodes digital waveforms internally; only the rig mode command differs.

Implementation

  • Configuration.hpp — added data_mode_CW to the DataMode enum
  • Configuration.cpp — registered the CW radio button in the TX mode button group; added case data_mode_CW to set_cached_mode() which maps it to Transceiver::MODE_CW
  • Configuration.ui — added mode_CW_radio_button to the Mode group box (row 0, column 3)

4. TX Shift ±200 MHz

The TX Shift spinbox in the Astronomical Data window has been extended from ±30 MHz to ±200 MHz. This allows EME microwave stations to operate with large frequency offsets between RX and TX, which is common with separate transverters or different LO chains for uplink and downlink.

Implementation

  • widgets/astro.ui — changed sbibShift QSpinBox minimum from −30 to −200 and maximum from 30 to 200

TX Shift display fix v3.0.3

When “Enable Shift” is checked, the Sked TX frequency label now shows the actual shifted TX frequency (RX + Shift) in blue text instead of the previous uninformative “N/A Tx Shift!” message.

5. Fine Frequency Control (Mouse Wheel)

The dial frequency mouse wheel now supports modifier keys for sub-kHz tuning steps:

ModifierStep Size

Ctrl10 Hz

This allows precise frequency adjustment for EME CW without needing to type exact values or use rig controls.

6. CW Mode Status Indicator

A CW label appears in the main window status bar when CW data mode is active in Settings > Radio > Mode. The label is hidden when any other mode is selected, providing clear visual confirmation of the operating mode.

7. Per-Callsign QSO Log

The QSO log file is now named based on the callsign configured in Settings > General:

wsjtx_log_II9P.adi    (callsign = II9P)
wsjtx_log_W1ABC.adi   (callsign = W1ABC)
wsjtx_log.adi         (no callsign set — fallback)

Behavior

  • When the callsign changes in settings, the program automatically switches to the corresponding log file.
  • Existing log files are reused; new ones are created automatically.
  • Each callsign’s QSO history is kept separate, which is useful for multi-callsign stations or contest operations.

Implementation

  • logbook/WorkedBefore.hpp/.cpp — added set_callsign() slot and update_path() for dynamic log file switching
  • logbook/logbook.h/.cpp — forwarding set_callsign()
  • widgets/mainwindow.cpp — calls set_callsign() on callsign change

8. Cabrillo Export with Log Source Selector

The File > Export Cabrillo log dialog now includes a Log source combo box at the top. It lists:

  • (Contest log) — the original internal SQLite contest log (default, preserving existing behavior)
  • All wsjtx_log*.adi files found in the WSJT-X data directory

When an ADI log file is selected, the dialog parses its ADIF records and writes them as Cabrillo 3.0 QSO lines. Exchange fields are auto-detected:

PriorityExchange SentExchange Received
1 (highest)STX_STRINGSRX_STRING
2STXSRX
3 (fallback)RST_SENTRST_RCVD

The combo box automatically pre-selects the ADI file matching the current callsign in Settings.

9. Language Selector

A Language combo box has been added to Settings > General with two options:

  • System default — uses the operating system locale (original WSJT-X behavior)
  • English — forces the UI to English regardless of OS locale

Changing the language requires a restart of WSJT-X because Qt translations are loaded at startup. A message box reminds the user when the selection changes.

Implementation

  • The language preference is stored in QSettings as UILanguage (empty string for system default, "en" for English).
  • In main.cpp, the setting is read before creating L10nLoader and passed as the language override. The existing L10nLoader skip-locale logic handles forcing English when the override is "en".
  • The -l command-line flag continues to work and takes priority if the stored setting is “System default.”

10. Fixed Frequency Offset

A new Offset tab has been added to the Settings dialog, providing two independent controls:

  • RX offset — added to the receive frequency sent to the radio
  • TX offset — added to the transmit frequency

Both values are in Hz and range from −100 MHz to +100 MHz (step size: 1000 Hz). They are applied alongside station offsets before the calibration correction:

RIG_freq = calibration(dial_freq + station_offset + fixed_offset)

Typical uses

  • Transverter IF offsets where the RX and TX chains use different LO frequencies
  • Fixed frequency corrections for EME microwave setups
  • Any scenario requiring a constant shift between the displayed frequency and the frequency sent to the radio

Implementation details

  • Stored in QSettings as FixedRxOffset and FixedTxOffset (FrequencyDelta / qint64)
  • Applied in transceiver_frequency() and transceiver_tx_frequency()
  • Subtracted in the rig feedback handler to prevent accumulation on each polling cycle

11. Offline Operation & Rig Failure Handling

WSJT-X can now be used productively without a physical radio connected:

Band frequency display

When no rig is connected, switching bands shows the correct default frequency for the selected band. Previously, the display showed a stale or meaningless value because it read from the rig state object, which was never updated.

Split with “None” rig

Split operation is now available when rig is set to “None” in Settings > Radio. This is enabled at build time via the WSJT_RIG_NONE_CAN_SPLIT=ON CMake option. With split enabled, Doppler tracking calculations work correctly.

Doppler tracking without rig

Doppler corrections are computed and stored in m_astroCorrection even when the rig is set to “None”, regardless of monitoring or transmitting state. The corrections are visible in the Astronomical Data window.

Rig failure handling

When a selected rig is unavailable (e.g., COM port not connected), the previous behavior was an infinite loop of error dialogs. The new behavior:

  1. First failure: show the error dialog once
  2. Subsequent failures: silently ignored — the program continues without a rig
  3. The counter resets when a rig successfully connects or when the user explicitly clicks “Retry”

All transceiver failure handling is centralized in the main window. The Configuration dialog no longer shows its own error dialog, preventing duplicate popups.

14. Building from Source

Requirements

  • Windows 10/11 64-bit
  • CMake 3.10+
  • Qt 5.15.2 with MinGW 8.1.0 64-bit
  • Boost 1.74 (log, stacktrace, timer)
  • FFTW 3.3.5 (64-bit DLL)
  • Hamlib 4.x (pre-built Windows 64-bit)
  • libusb 1.0.x
  • libbacktrace 1.0
  • OmniRig (type library for COM interface)

Build commands

set PATH=C:\Qt\Tools\mingw810_64\bin;%PATH%

mkdir build-wsjtx && cd build-wsjtx

cmake -G "MinGW Makefiles" ^
  -DCMAKE_TOOLCHAIN_FILE=C:\Tools\wsjtx-toolchain.cmake ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DWSJT_SKIP_MANPAGES=ON ^
  -DWSJT_GENERATE_DOCS=OFF ^
  -DWSJT_SKIP_MAP65=ON ^
  -DWSJT_RIG_NONE_CAN_SPLIT=ON ^
  -DOMNIRIG_TYPE_LIB=C:\Tools\omnirig-extracted\app\OmniRig.exe ^
  -DCMAKE_INSTALL_PREFIX=C:\Tools\wsjtx-install ^
  C:\src\wsjtx

cmake --build . -j8
cmake --build . --target install

The toolchain file wsjtx-toolchain.cmake is included in the repository. Edit it to match your local dependency paths.
