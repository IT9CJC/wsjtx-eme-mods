1. Overview

This is a modified build of WSJT-X 3.0.2 with two additions for EME (Earth-Moon-Earth) CW operation:

  1. CW rig mode via CAT — a new "CW" radio button in Settings > Radio that commands the transceiver into CW mode through Hamlib, while keeping full Doppler tracking active on both RX and TX.
  2. Extended TX Shift to ±200 MHz — the TX Shift control in the Astronomical Data window now accepts values from −200 to +200 MHz (stock limit is ±30 MHz).

Why is this needed?

Stock WSJT-X supports Doppler-tracked digital modes (JT65, Q65, etc.) for EME, but has no provision for setting the rig to CW mode via CAT while Doppler tracking remains active. EME CW operators must compensate for the continuously changing Doppler shift on the Earth-Moon-Earth path (up to ±several kHz at microwave frequencies). This mod lets WSJT-X handle that automatically while the operator works CW.

The extended TX Shift range is useful on microwave bands where the TX and RX frequencies may be separated by far more than 30 MHz due to transverter offsets or deliberate frequency splits.

What is not changed

  • All existing WSJT-X digital modes and features work exactly as before.
  • The Doppler correction engine is unchanged — CW mode simply reuses the existing infrastructure.
  • Hamlib rig control is unchanged — the Transceiver::CW enum value already existed and maps to RIG_MODE_CW.

2. Installation

  1. Download wsjtx-eme-mods-win64.zip from the GitHub Releases page.
  2. Extract the ZIP to any location (e.g. C:\wsjtx-eme).
  3. Run bin\wsjtx.exe.
Note All required DLLs (Qt, Hamlib, Boost, FFTW, MinGW runtime) are bundled in the bin\ directory. No separate runtime installation is needed.
Side-by-side with stock WSJT-X This build uses the same configuration directory as stock WSJT-X (%LOCALAPPDATA%\WSJT-X). If you want to keep both, back up your settings before first launch, or use the --rig-name command-line option to create a separate configuration instance: 
wsjtx.exe --rig-name=EME-CW

3. CW Mode Setup

  1. Open File > Settings (or press F2).
  2. Go to the Radio tab.
  3. In the Mode group box, select the CW radio button.

The four available mode options are:

ButtonCAT Mode SentUse Case
None(no mode change)Leave rig mode as-is
USBUSBSSB digital modes
Data/PktDIG-U (DATA-USB)FSK/AFSK digital modes
CW NEWCWEME CW with Doppler tracking

When CW is selected, WSJT-X sends RIG_MODE_CW to the transceiver via Hamlib every time it updates the frequency (which happens continuously during Doppler tracking). The rig stays in CW mode, and frequency corrections are applied via CAT.

CW mode status indicator

When CW mode is active, a CW label appears in the main window status bar (next to the digital mode label). This provides a quick visual confirmation that the rig is being commanded to CW mode via CAT. The label is hidden when any other mode is selected. NEW

4. Doppler Tracking

Opening the Astronomical Data window

Go to View > Astronomical Data to open the Doppler tracking window. This window shows Moon position, Doppler shift, path loss, and provides the tracking controls.

Grids

Enter your own Maidenhead grid in Settings > General and the DX station's grid in the Astronomical Data window. WSJT-X uses both grids to compute the precise Doppler shift on the Earth-Moon-Earth path.

Doppler tracking methods

The Doppler tracking dropdown selects how frequency corrections are applied:

MethodDescriptionTypical Use
Full Doppler to DX GridCorrects RX and TX for full round-trip Doppler to the DX station's gridWhen DX does not correct
Constant frequency on MoonSignal arrives at the Moon at the nominal frequencySelf-echo, beacons
Own EchoCorrects for your own echo return DopplerEcho testing
Both stations correctEach station corrects half the DopplerBoth stations running tracking software
On DX EchoCorrects so DX hears their own echo on frequencyCooperative EME
Split mode required Doppler tracking applies separate RX and TX frequency corrections. Your rig must be in split mode (VFO A for RX, VFO B for TX) for TX corrections to take effect. Enable split in Settings > Radio > Split Operation.

How corrections are applied

WSJT-X computes two independent correction values (in Hz):

  • RX correction — added to the nominal RX frequency: f_rx = f_nominal + correction.rx
  • TX correction — added to the nominal TX frequency: f_tx = f_nominal + correction.tx

These corrections are sent to the rig via CAT at each update cycle (typically every second). The corrections are independent of rig mode — they work identically whether the rig is in USB, Data, or CW.

5. TX Shift

The Tx Shift spinbox in the Astronomical Data window applies a fixed frequency offset to the TX frequency, on top of any Doppler correction.

ParameterValue
Range−200 to +200 MHz EXTENDED
Step size1 MHz
Internal unitHz (value × 1,000,000)
Enable checkbox"Enable Shift" must be checked

The TX Shift is useful when:

  • Your TX and RX frequencies are offset by a transverter LO difference.
  • You are working cross-band or with a large deliberate frequency split.
  • You need to compensate for equipment-specific frequency offsets on microwave bands.
Shifted frequency display When "Enable Shift" is checked, the Sked TX frequency label in the Astronomical Data window shows the actual shifted TX frequency (RX + Shift) in blue text, so you can verify the applied offset at a glance. When shift is disabled, the label returns to its normal color.
Original limit was ±30 MHz Stock WSJT-X limits the TX Shift to ±30 MHz. This mod extends it to ±200 MHz for microwave EME use. The underlying Doppler correction engine handles the full range without modification.

Tip for EME CW The 1 Hz and 10 Hz steps are particularly useful for setting the exact nominal frequency before enabling Doppler tracking, ensuring your signal lands precisely where expected on the Moon bounce path.

When you change the callsign in Settings, the program automatically switches to the corresponding log file. If a log with that name already exists, new QSOs are appended to it. If it does not exist, a new file is created on the first logged QSO.

Multi-station operation This feature is useful when operating under different callsigns (e.g. a personal call and a club call). Each callsign maintains its own "worked before" database, so DXCC/grid/call highlighting is accurate per station.

6. EME CW Operating Procedure

Step-by-step guide for EME CW operation with Doppler tracking:

6.1 Initial setup (one-time)

  1. Open Settings (F2).
  2. General tab: Enter your callsign and Maidenhead grid locator.
  3. Radio tab:
    • Select your rig from the Hamlib dropdown.
    • Configure the serial port (or network address for TCP rigs).
    • Set Mode to CW.
    • Set Split Operation to Rig or Fake It.
    • Configure PTT method (CAT, DTR, RTS, or VOX).
  4. Click Test CAT to verify communication. The button should turn green.

6.2 Before each session

  1. Tune your rig to the desired nominal frequency (e.g. 144.100 MHz, 432.000 MHz, 1296.000 MHz).
  2. Open View > Astronomical Data.
  3. Enter the DX station's grid locator (or leave blank for CQ).
  4. Select the appropriate Doppler tracking method:
    • Use Full Doppler to DX Grid if you know the DX grid and the DX station is not tracking.
    • Use Both stations correct if both of you run tracking.
    • Use Own Echo for testing your own echoes.
  5. If needed, set Tx Shift (check "Enable Shift" and enter the value in MHz).
  6. Click Track to start Doppler tracking.

6.3 During the QSO

  • WSJT-X continuously updates the rig frequency via CAT. You will see the VFO moving as the Doppler shift changes.
  • Operate CW normally — use your keyer, paddle, or straight key.
  • The Astronomical Data window shows the current Doppler shift, predicted echo delay, and path degradation in real time.
  • If the DX station moves to a different grid, update the grid field and the tracking will adjust immediately.

6.4 After the QSO

  • Click Stop in the Astronomical Data window to stop tracking.
  • Log the QSO as usual.

7. CAT / Hamlib Configuration

WSJT-X uses Hamlib 4.7.2 (bundled) for rig control. The CW mode mapping is:

User selects "CW" in Settings
  → Configuration sets data_mode_CW
  → set_cached_mode() maps to Transceiver::CW
  → HamlibTransceiver::map_mode() sends RIG_MODE_CW
  → Hamlib issues the appropriate CAT command for your rig
     (e.g. "MD3;" for Kenwood, 0x06 for Icom CI-V)

8. Frequency Resolution

Doppler corrections are rounded to match the minimum frequency step your rig supports via CAT. WSJT-X queries the rig's tuning resolution from Hamlib and applies the following rounding:

Rig ResolutionCorrection Rounded To
100 Hz or coarserNearest 100 Hz
20 HzNearest 20 Hz
10 HzNearest 10 Hz
1 HzNearest 1 Hz

On microwave bands where Doppler rates are high, a rig with 1 Hz resolution provides the smoothest tracking. Most modern HF/VHF transceivers support 1 Hz or 10 Hz CAT resolution.

9. Troubleshooting

Rig does not switch to CW mode

  • Verify CW is selected in Settings > Radio > Mode.
  • Click Test CAT — green means CAT is working.
  • Some rigs require specific baud rate or handshake settings. Consult your rig manual and the Hamlib documentation.
  • Check that your rig model is correctly selected (not "Dummy" or a wrong model).

Doppler corrections not applied to TX

  • Split mode must be enabled. Go to Settings > Radio and set Split Operation to "Rig" or "Fake It".
  • Verify that Doppler tracking is active (click "Track" in the Astronomical Data window).

TX Shift has no effect

  • The "Enable Shift" checkbox must be checked.
  • TX Shift only applies to certain Doppler methods. Select the appropriate tracking method in the Astronomical Data window.

VFO not moving / frequency frozen

  • Make sure WSJT-X is in Monitor mode (click Monitor or press F4). Doppler corrections are only sent when monitoring or transmitting.
  • Check that the rig is online (green circle in the bottom status bar).

"Test CAT" fails (red button)

  • Check serial cable and port number.
  • Verify baud rate matches the rig setting.
  • Close any other programs that might be using the same COM port.
  • Try a different rig model in the Hamlib list (some rigs have multiple entries for different firmware versions).

10. Building from Source

The source code is available at github.com/IT9CJC/wsjtx-eme-mods.

Requirements

  • Windows 10/11 64-bit
  • CMake 3.10+
  • Qt 5.15.2 with MinGW 8.1.0 64-bit
  • Boost 1.74 (log, stacktrace, timer)
  • FFTW 3.3.5 (64-bit DLL)
  • Hamlib 4.x (pre-built Windows 64-bit)
  • libusb 1.0.x
  • libbacktrace 1.0
  • OmniRig (type library for COM interface)

Build commands

set PATH=C:\Qt\Tools\mingw810_64\bin;%PATH%

mkdir build-wsjtx && cd build-wsjtx

cmake -G "MinGW Makefiles" ^
  -DCMAKE_TOOLCHAIN_FILE=C:\Tools\wsjtx-toolchain.cmake ^
  -DCMAKE_BUILD_TYPE=Release ^
  -DWSJT_SKIP_MANPAGES=ON ^
  -DWSJT_GENERATE_DOCS=OFF ^
  -DWSJT_SKIP_MAP65=ON ^
  -DOMNIRIG_TYPE_LIB=C:\Tools\omnirig-extracted\app\OmniRig.exe ^
  -DCMAKE_INSTALL_PREFIX=C:\Tools\wsjtx-install ^
  C:\src\wsjtx

cmake --build . -j8
cmake --build . --target install

The toolchain file wsjtx-toolchain.cmake is included in the repository. Edit it to match your local dependency paths.
